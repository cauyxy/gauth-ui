# Gauth design system

The rules every Gauth page follows, the tokens they use and the shared components that carry them. The values live in `src/styles/tokens.css`; this folder says how to use them.

- `tokens.json`: every token as data, generated by `pnpm tokens`. The docs site's Tokens page reads it. `pnpm test` fails when it falls behind.
- `components/<Name>/README.md`: when to use each component.

The look follows gauth.com: white ground, ink text, hairline-edged cards instead of drop shadows, and the red Gauth mark as the only red on the page.

## Content

- **Every screen answers "what do I do next?"** Lead with the problem and end with one action.
- **Say the next step.** A row ends with one button with one or two verbs ("Reteach", "Review", "Remind"). Not "Click here" or "Submit".
- **No unnecessary secondary labels or descriptions.** Leave out a label the layout already explains.
- **Proof points are specific.** A real count and a place beat adjectives. Never round up, and never use a number without its source.
- **A wrong answer is "Not yet".** Name the step that went wrong and offer the next try. Never show a score drop.
- **One thing has one name everywhere.** The same few words describe a skill, a level or a mistake on every page and in every product.
- **Don't sell AI.** Say where a thing came from and what was checked.
- **Write for the reader's place.** A US classroom reads "Geometry · Period 3", "due Thu", "Fri, Oct 23". A change in a share reads "+8 pts", not "+8%".

## Color

Ink on white carries the page. Color appears only where it means something. A token is `var(--gx-color-<name>)` in CSS and `bg-<name>` / `text-<name>` in Tailwind.

| Meaning      | Tokens                                                              | Where                                                                                             |
| ------------ | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Text         | `ink`, `ink-soft`, `muted`, `faint`                                 | `ink` for text and primary buttons; `muted` for meta lines; `faint` never for running text.       |
| Surfaces     | `canvas`, `surface`, `line`                                         | White cards on `canvas`; `surface` for soft cards, row hover, secondary buttons and icon squares; `line` for dividers. |
| Edges        | `edge`, `edge-strong`, `ring`, `rule`, `track`                      | Card outlines are an inset 1px shadow (`shadow-edge`); `rule` for firmer lines and off toggles; `track` is the empty part of any bar or level mark, the not-started part of a level bar and the ground of a Segmented control; it has the value of `line`. |
| Brand        | `brand`                                                             | The Gauth mark only. Never text, buttons or states.                                               |
| Skill levels | `attempted`, `familiar`, `proficient`, `mastered`                   | Level marks and level bars. See Skill levels.                                                     |
| XP and AI    | `violet`, `violet-deep`, `violet-soft`                              | XP and Gauth AI accents. Never a level, never a button.                                           |
| Standards    | `blue`, `blue-soft`                                                 | Standard-code chips and links. The focus ring.                                                    |
| Done, right  | `good`, `good-soft`, `good-mid`, `correct`                          | Checked, the right answer, a positive delta.                                                      |
| Look here    | `warn`, `warn-soft`                                                 | Something that needs a person's eyes.                                                             |
| Celebration  | `pink`, `pink-soft`                                                 | Celebration moments only.                                                                         |

- **One solid ink button per view.** Every other action is `soft` or `outline`. Never red, never violet.
- Nothing on a page is red except the mark.

## Skill levels

One ladder in every product: **Attempted, Familiar, Proficient, Mastered**, plus Not started for no evidence yet.

| Level       | Fill          | Text on soft     | Soft              |
| ----------- | ------------- | ---------------- | ----------------- |
| Mastered    | `mastered`    | `mastered-ink`   | `good-soft`       |
| Proficient  | `proficient`  | `mastered-ink`   | `good-soft`       |
| Familiar    | `familiar`    | `familiar-ink`   | `familiar-soft`   |
| Attempted   | `attempted`   | `attempted-ink`  | `attempted-soft`  |
| Not started | `track`       | `muted`          | `surface`         |

- The ramp runs from warm to cool: orange, gold, mint, teal.
- `attempted` is also the color of a wrong answer and of a field error. There is no separate error color, and nothing is red.
- Each level also has its own shape, so no level relies on color alone.
- Text in a level's color uses its `-ink` value on its `-soft` ground. Mastered and Proficient share one ink and the ground of done and right (`mastered-ink` on `good-soft`): their fills, their marks and their names tell them apart, and no soft ground of their own did.

## Type

Google Sans (`--gx-font-sans`), loaded from Google Fonts by each product, with a metric-matched fallback so text does not shift when it loads. Mono (`--gx-font-mono`) for worked steps. The page keeps the browser's `normal` line height.

A reading passage (a story, an article, a source text) can be set in Literata (`--gx-font-reading`): `<Prose font="reading">`, and nowhere else. A control, a label, a page's title and a math lesson stay in Google Sans. A product that sets a passage loads Literata beside Google Sans; until it loads, the passage is in Georgia, which is not metric-matched, so its lines can break again once.

| Token  | Size  | Role                                                         |
| ------ | ----- | ------------------------------------------------------------ |
| `6xl`  | 60 px | Marketing hero                                               |
| `5xl`  | 48 px | Marketing section titles                                     |
| `4xl`  | 36 px | Student page titles                                          |
| `3xl`  | 30 px | Page titles on phones, metrics                               |
| `2xl`  | 24 px | Staff page titles, question stems                            |
| `xl`   | 20 px | Dialog and sheet titles, a heading in long text              |
| `lg`   | 18 px | Student reading size: problems, steps, answers. Panel titles |
| `base` | 16 px | Student body, phone inputs                                   |
| `sm`   | 14 px | Staff rows, buttons, nav, table cells                        |
| `xs`   | 12 px | Meta, chips, small labels                                    |
| `2xs`  | 11 px | Captions, column heads, chart labels                         |
| `3xs`  | 10 px | Print sheets and tiny badges only                            |

Weights: 400 for body, 500 for controls (buttons, chips, labels, table rows), 600 for panel and card titles, 700 for page titles, dialog and sheet titles, and metrics. Controls are medium, not bold: a page full of semibold reads heavy. Figures that line up use tabular numbers. A size that is not on the scale goes to the nearest step.

Line height has four steps: `leading-figure` 1 for a metric, `leading-title` 1.15 for a page title, `leading-heading` 1.35 for a card title or an answer option, `leading-body` 1.5 for running text. Tracking has three: `tracking-display` −0.03em for page titles and metrics, `tracking-title` −0.02em for card titles, `tracking-label` +0.025em for column heads.

- A title balances its lines (`text-wrap: balance`), so a phone never leaves "3?" alone on the last line. Running text in a callout, a hint or a description uses `text-wrap: pretty`.
- A middle dot stays with the word before it: write a non-breaking space before "·", so a line never starts with the dot.
- Long text (a lesson, an explanation, a reading passage) is a `Prose`: it sets the headings, lists, quotes, figures and tables inside it, at most `container-read` wide. Do not style those elements again on a page.
- A column of numbers is right-aligned with tabular numbers.
- No `-webkit-font-smoothing: antialiased`: on macOS it makes the stems thin and washed out.

## Formulas

- KaTeX draws every formula. `Tex` for one formula, `RichText` for words with formulas in them.
- A formula in a line of words stands on their baseline, and its numbers are as tall as theirs. KaTeX's own size (1.21em) is for a serif text face; next to Google Sans it is 1.1em.
- A formula is ink, or the color of the text it is in. Words and units inside a formula are the face of the words around it: Google Sans, or Literata in a reading passage. Literata's numbers are as tall as Google Sans's, so the formula keeps its 1.1em there.
- A formula on its own line is centered and scrolls in its own box when it is wider than the page. The box then takes keyboard focus, so the arrow keys scroll it.
- The punctuation after a formula stays on the formula's line.

## Gauth AI

- The assistant is "Gauth AI", in every product and language.
- **Don't sell AI.** No sparkle, no gradient, no glow, no text that pulses. A status line says what is being done in plain words ("Reading 28 answers"), with a spinner, and then what was done.
- A person's message is a soft bubble at the end side. Gauth AI's reply is plain text on the page, with no bubble: it is content, not a chat.
- Under a reply: the votes and copy, as quiet icon buttons. Under the last reply: questions to tap.
- While Gauth AI writes, Send becomes Stop.
- Every composer has the line that says to review AI output.

## Optical alignment

Align what the eye sees, the ink, not the box. `node gallery/optical.ts` measures it in Chrome and fails when a place is off by half a pixel or more.

- **A label in a control.** The control's middle lies between the middle of the capitals and the middle of the lowercase letters. Google Sans does this by itself at the four control heights, so a label needs no nudge. Do not set a `line-height` on a one-line label to "fix" it.
- **A letter or number in a round mark** (an answer's letter, a step's number, initials): the capitals' middle is the mark's middle, both ways.
- **A mark beside text** (a checkbox, a level mark, a spinner): its middle is on the first line of the text. When the text wraps, the mark stays on the first line; it does not move to the middle of the block.
- **A formula in a line of words:** one baseline, and numbers of one height (within 5%).
- **An icon at the end of a control.** An icon's strokes do not fill its 20px box, so the icon sits 2px closer to the edge than text does. `Button` and `Select` do this by themselves.
- **One icon family: Lucide.** 20px, a 1.8px stroke, round ends, never filled. `Icon` holds the icons the components and most pages need. A product that needs another one takes it from Lucide and draws it the same way: `strokeWidth={2.16}` (1.8px at 20px; like `Icon`, the stroke grows with the size). An icon from another family sits wrong next to them.

## Surfaces and layout

- **Keep it light.** A grey fill, an outline and a bold weight each add weight, so an element gets one of them at most. A plain chip has an outline and no fill. A table's column heads have no fill. A picked option stays white and only its mark turns ink.
- The hairline has two strengths: `edge` (10%) around cards, `edge-strong` (14%) around a control.

- Staff cards are `Panel`: 16px radius, white, a 1px inset hairline, no drop shadow. Student cards are `StudentCard`: 24px radius, and a soft ground in place of the hairline when the card has one of the meanings below (see Learning).
- Nested radii are concentric: a card holds tiles a step smaller. Radii: `xs` 2 · `sm` 4 · `md` 6 · `lg` 8 · `xl` 12 · `2xl` 16 · `3xl` 24 · `4xl` 32 px.
- Shadows are only `card`, `edge`, `edge-strong`, `pop`, `raise`, `outline`, `box` (an empty checkbox) and `invalid` (a field with an error). `shadow-pop` is for popovers, menus and floating docks.
- Lines between rows are borders in `line`, not shadows. A picked item is `shadow-outline` (1.5px ink).
- Controls have four heights: `--gx-h-sm` 30, `--gx-h-md` 34, `--gx-h-lg` 40, `--gx-h-xl` 44px. Staff pages use `md`; student pages and touch targets use `xl`.
- **Spacing is a 12-step scale** (`--gx-space-*`): 2, 4, 6, 8, 10, 12, 14, 16, 20, 24, 32, 40px. Inside a control use 4 to 12; between rows 12 to 16; inside a card 20 to 24; between sections 32 to 40.
- **Three content widths:** `container-read` 720px for a question, a lesson or a form; `container-doc` 960px for a plan or a review; `container-page` 1600px for an app shell.
- **Three layers:** `z-overlay` for a dialog and its scrim, `z-pop` for a popover, menu or tooltip (also when it opens from a dialog), `z-toast` above everything.
- Rows of cards share top and bottom edges. When one card is taller, the shorter one stretches and its action sits at the bottom.

## Motion

Motion says what changed and then stops. It is short, it never loops for decoration, and it never delays the next action.

| Token       | Time   | Use                                                              |
| ----------- | ------ | ---------------------------------------------------------------- |
| `dur-fast`  | 150 ms | Hover, color, a chevron's turn, a popover or tooltip opening     |
| `dur-base`  | 200 ms | A change in place: a picked answer, a fade                       |
| `dur-enter` | 260 ms | Content that arrives: a drawer, a revealed hint, a card          |
| `dur-mark`  | 360 ms | Feedback on an answer                                            |

- Two easings: `ease-standard` for a change in place, `ease-enter` for content that arrives (fast at first, then it settles).
- Named movements (`--gx-animate-*`, `animate-*` in Tailwind): `fade-in`, `fade-out`, `pop-in`, `pop-out`, `tip-in`, `rise-in`, `slide-in`, `slide-in-end`, `pulse`, `spin`, `sweep`, `mark-right`, `mark-retry`.
- Things leave faster than they arrive: an exit is `dur-fast`.
- **A right answer** gets one small swell (`mark-right`). **A wrong answer** gets a short side-to-side nudge (`mark-retry`) in the `attempted` orange, never red, and the words "Not yet".
- **Only three things loop:** a skeleton's pulse, a spinner, and the segment of a bar with no known end. Each one means "wait".
- Hover changes color only. Text never moves or changes size on hover.
- When a person asks for reduced motion, every duration is 0: changes are instant and loops stop.

## Focus and contrast

- **One focus ring:** 2px `blue`, 1 or 2px away from the control, on keyboard focus only. A field shows it too.
- **A group is one Tab stop.** Arrow keys move inside a Segmented control, tabs, a menu and a set of answer options.
- **Text reaches 4.5:1 on its ground.** `ink`, `ink-soft` and `muted` pass on white, `canvas` and `surface`. A tone's text passes on its own `-soft` ground. `faint` and `good-mid` are for marks and lines, never text.
- **A level's fill carries ink, never white.** White on `attempted` is 2.1:1. A letter or a check on a level's fill or on `correct` is ink.
- A state is never color alone: a level has a shape, a right answer has a check and the word "Correct", a wrong answer has the words "Not yet", a field error has its text.

## Language

- Components speak English and Spanish. A product sets `<LocaleProvider locale="es">` once.
- A word a component says by itself comes from one list (`src/core/messages.ts`), so "Not yet" and "Proficient" read the same in every product. `GLOSSARY.md` says what each word means and what not to say instead.
- Dates and deltas come from `useLocale()`: "Fri, Oct 23" and "+8 pts" in English, "vie, 23 oct" in Spanish.
- A translated label can be a third longer. Do not fix a width around a word.

## Learning

What every education page shares: the icons for the work, the marks of progress, and how a subject looks.

**Icons for the work.** One name for each thing a student does or a teacher gives, so a lesson has the same icon in every product. The names say what the icon is for; the drawings are Lucide's.

| Icon | For |
| ---- | --- |
| `lesson`, `course` | A lesson; a course or a unit's library |
| `assignment`, `practice`, `quiz`, `checklist` | Work a teacher gives; practice a student does; a check of what they know; a list of steps to finish |
| `hint`, `question` | A hint under a question (with `Reveal`); asking about a step |
| `goal`, `report`, `timer` | A daily or weekly goal; a report or a chart of progress; time on a task |
| `scan`, `camera` | Taking a photo of a problem, the way Gauth starts |
| `video`, `bookmark`, `flag` | A video lesson; something saved for later; a question reported or marked for review |
| `school`, `graduation` | A school or a class; finishing a course |
| `streak`, `xp`, `trophy`, `badge` | Days in a row; XP; a finished challenge; an earned badge |

**Subjects.** A subject is an icon and its name: `subject-math`, `subject-geometry`, `subject-science`, `subject-reading`, `subject-language`, `subject-social-studies`, `subject-art`, `subject-music`. Tools: `calculator`, `ruler`.

- A subject has no color of its own. Color on a learning page means a level, a right answer, XP or a celebration; a blue Math and a green Science would compete with them. Put the subject's icon in an `IconBox` beside its name.
- Write the course as the school writes it ("Algebra 1", "English 9"), not the subject alone.

**Progress and reward.**

- A level is always the level ladder (`LevelMark`, `LevelChip`, `LevelBar`): Attempted, Familiar, Proficient, Mastered. A percent or a grade never stands in for a level.
- XP, a streak and a badge are `violet` (`Chip tone="violet"`, `IconBox tone="violet"`). They count effort, so they never use a level's color and never go down.
- A celebration (a finished unit, a badge earned) is `pink`, once, at the moment it happens.
- After an answer comes an `AnswerFeedback`: "Correct" on `good-soft` with the reason, or "Not yet" in `attempted` orange with the next try. Never red, never a lost point or a broken streak shown in red.
- A goal reads as what is left: "2 more questions today", with a `Meter` or a `StepProgress`.

**Where color has room.** On a student page four meanings may fill a whole `StudentCard` with their soft ground, so the page is not all white and grey:

| Meaning                   | Ground               | How                                           |
| ------------------------- | -------------------- | --------------------------------------------- |
| A goal, XP, a streak      | `violet-soft`        | `<StudentCard tone="violet">`                 |
| Done, a right answer      | `good-soft`          | `<StudentCard tone="good">`, `AnswerFeedback` |
| A level a student reached | that level's `-soft` | `<StudentCard level="proficient">`            |
| A celebration             | `pink-soft`          | `<StudentCard tone="pink">`                   |

- Nothing else takes a ground. A subject, a lesson, a setting or a plain fact stays on a white card, and its icon stays neutral.
- Two soft cards at most on a screen where a student works; four at most on a summary. When every card has a color, none of them says anything.
- The colors are the ones above. No new color for a subject, a course or a product.
- A staff page stays ink on white: color there is a chip, a level or a mark.

**Where the work lives.**

- A student page uses `xl` controls, `lg` (18px) reading text and 24px card radii; a staff page uses `md`, `sm` and 16px.
- A question, a lesson or a form is at most `container-read` (720px) wide.
- A student sees one next step: one `ink` button ("Start", "Keep going"), every other action `soft`.
